## Findings fixed in this audit (same day)
1. **Low-stock threshold was hard-coded (`stock <= 5`)** in reports, admin inventory and
   storefront badges → added `Product.lowStockThreshold` (default 5, 0 = disabled), editable in
   Admin → Inventory, used by the dashboard "Low stock" card (column-vs-column SQL count), the
   inventory Low-stock tab, product cards and buy box. Migration
   `20260909_low_stock_threshold_first_order_coupon` (additive).
2. **First-order discount missing** (spec §4) → added `Coupon.firstOrderOnly`: signed-in customers
   only; any previous non-cancelled order disqualifies; enforced inside `evaluateCoupon` (runs at
   cart preview AND authoritatively at order creation); admin UI checkbox + "First order" badge.

## Verified clean (sweep evidence)
- No hard-coded secrets (live/test key patterns, AKIA…, xox…): only `src/lib/env.ts` validation
  strings that *refuse* mismatched Razorpay key modes per environment.
- No TODO/FIXME/HACK markers in `src/**`.
- Raw SQL limited to: atomic coupon-usage increment, job claim (SELECT … FOR UPDATE SKIP LOCKED),
  low-stock count — all static statements with bound parameters (no interpolation).
- Rate limiting on register/login/reset/coupon/upload/contact; in-memory per instance (documented
  limitation for multi-instance scaling).
- Webhooks: Razorpay HMAC verified; supplier webhook HMAC-SHA256 verified + REJECTED events
  persisted; CJ webhooks unsigned by design → trigger-only re-fetch (payloads never trusted).
- Cron endpoint: Bearer `CRON_SECRET`, timing-safe compare (E2E-verified 401/200 paths).
- Uploads: magic-byte sniffing, 5 MB cap, random names, provider abstraction, DELETE endpoint.
- Notifications: never pretend delivery — `console` provider logs; SMTP failures recorded as
  FAILED with error; status visible in Admin → Logs.
- Analytics: gross margin never labelled profit; net profit comes from the per-order finance
  ledger and is flagged as an estimate until orders finalize.

## Known limitations (honest list — not bugs)
- Per-product COD/return/prepaid flags (§5) are **global-only** today: COD availability/fee from
  Settings → Shipping & COD, return window from Settings → Policies. Per-product overrides would
  be a schema + checkout change; deliberately not rushed in this pass. Label: PARTIALLY AUTOMATED
  at global level.
- Search sorting covers featured/newest/price-asc/price-desc/popular/in-stock; a dedicated
  "discount %" sort is not offered (discounts are visible via compare-at prices).
- Rate limits and job locks are single-instance-safe (correct for the current Vercel cron-driven
  architecture); multi-instance horizontal scaling would need Redis-class shared state.
- Featured products = admin-curated via `sortOrder` (no ML ranking — by design, per the pricing
  correction: no "what will sell" prediction claims anywhere).
- Local-disk uploads remain ephemeral on serverless until `STORAGE_PROVIDER` is configured
  (USER_INPUT_REQUIRED.md B7).
